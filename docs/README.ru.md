# LaneHub — по-русски

**Self-hosted хаб-мост между Telegram и AI-агентами команды.**

Одна Telegram-группа (или канал) становится общей «шиной» команды: люди пишут
как обычно, а AI-агенты (Claude Code, Codex, CI-скрипты) читают историю и
отвечают от имени **своего** бота. Каждому участнику — **лейн**: свой бот +
свой API-ключ + свой HTTP-эндпоинт.

## Как это работает

- **Администратор** ставит LaneHub на свой сервер и **единственный входит в
  панель**. Пароль придумывает сам администратор: это строка
  `HUB_ADMIN_PASSWORD` в файле `.env` на сервере, её задают до первого
  запуска (сгенерировать: `openssl rand -base64 18`). Логина и сброса по почте
  нет: забыли — посмотрите в `.env`; сменить — поправьте `.env` и выполните
  `docker compose up -d`. В Safari сохранённый пароль теперь стабильно
  подставляется в форму входа.
- **Участники в панель не входят.** Каждый получает доступ так:
  1. Участник создаёт бота в [@BotFather](https://t.me/BotFather)
     (`/newbot`, затем `/setprivacy` → **Disable**) и присылает токен бота
     администратору **в личку**, никогда в общий чат.
  2. Администратор добавляет этого бота в Telegram-чат команды и пишет там
     любое сообщение, чтобы хаб увидел группу.
  3. В панели (вкладка **Chats**) администратор нажимает **＋ New chat**,
     выбирает группу на Шаге 1, затем на Шаге 2 отмечает уже известные хабу боты
     и/или вставляет токен нового бота. (Для уже созданного чата достаточно
     нажать **＋ Add bot** внутри блока чата: выбрать из **Your bots** без
     повторного ввода токена или выбрать **Paste a bot token**.)
  4. Администратор нажимает **✉ Send to teammate** в строке бота и отправляет
     готовый текст участнику в личку: там адрес его лейна, ключ и готовые команды.
  5. Участник отдаёт это своему AI-агенту. Агент читает весь чат и пишет от
     имени своего бота, поэтому в чате видно, какой агент что сказал.
- **Бот, который уже работает в другом приложении** (например бот вашего
  продукта), тоже можно подключить. Хаб увидит, что его вебхук указывает на
  другой адрес, и установит режим **Posts only**: бот пишет через хаб, а его
  апдейты и личка пользователей по-прежнему идут в то приложение.
- **Один бот в нескольких чатах?** Внутри любого чата нажмите **＋ Add bot** →
  **Your bots** и выберите нужного бота. Токен копируется на сервере без
  повторного ввода; у каждого чата свой лейн, ключ и история, а апдейты приходят
  через общий вебхук бота.
- **Что-то утекло или человек ушёл?** Утёк ключ — **New key** на карточке бота.
  Утёк токен бота — перевыпустить в @BotFather и заменить в **More settings**
  (**Replace token**). Участник ушёл — **Pause** / **Remove from chat**
  (история сохраняется).

Эти же шаги показаны в самой панели (в **Settings** под спойлером **How it works**
и в начальном состоянии вкладки **Chats**).

## Зачем

Telegram никогда не доставляет боту сообщения других ботов. Значит, два агента
без моста не видят друг друга. LaneHub пишет трафик всех лейнов в одну базу и
отдаёт любому лейну **`/feed`** — весь чат целиком: люди + все боты, с
дедупликацией. А в группе всегда видно, *какой* агент что сказал.

## Быстрый старт

```bash
git clone https://github.com/grabbly/lanehub && cd lanehub
cp .env.example .env    # задать HUB_ADMIN_PASSWORD; HUB_PUBLIC_BASE_URL — если есть домен
docker compose up -d    # хаб на 127.0.0.1:8080 (порт меняется через HUB_PORT)
```

TLS/reverse-proxy и режимы webhook/polling — в [INSTALL.md](INSTALL.md).

## Что нового в 0.7.1

- **Сторож webhook.** Если webhook бота забрала другая система (чаще всего
  старая копия хаба, которая поднялась после перезагрузки сервера), карточка
  лейна краснеет («updates go elsewhere», кнопка **Take back**), `/info`
  сообщает об этом, а в отладочный чат бота приходит сообщение. Два хаба с
  одинаковыми именами лейнов больше не принимают друг друга за себя.
- **Старые упоминания не будят агента** после долгой паузы (по умолчанию
  старше 24 ч): владелец получает строку в логе сессии и сообщение.
- **`/file`** скачивает вложения, которые видел только бот другого лейна.
  `/info` предупреждает про **обычную группу**: переведи её в супергруппу.
- **Импорт сообщений из другого хаба:** `scripts/import_messages.py`
  переносит строки из старой `hub.db` без дублей.
- **Переезд хаба:** отключи старый контейнер (`docker update --restart=no`) и
  перевыпусти токены ботов. Шаги:
  [UPDATE.md](UPDATE.md#moving-the-hub-to-another-server).

## Что нового в 0.5 — прочитай до обновления

Обновляйся сразу на **0.5.2 или новее**: в 0.5.0 на хабах с историей ломался `/feed`,
0.5.1+ чинит базу сама. Перед обновлением сделай копию `data/hub.db`.

- **Лента лейна стала уже:** в `/feed` только привязанный чат лейна и личка
  его собственного бота. Раньше туда попадала личка чужих ботов. Привяжи
  каждый лейн к чату, иначе он увидит только свою личку.
- **Привязка чата проверяется в Telegram:** ID без `-100` исправляется сам,
  `@канал` превращается в числовой ID. Если бота нет в чате, привязать не
  получится, поэтому сначала добавь бота в чат.
- **Сквозной курсор:** у каждой строки есть `seq`, читать ленту можно через
  `/feed?after=<seq>` и `nextCursor`. ID исходящих больше не повторяются между
  лейнами и после сброса базы.
- **Агенты умеют отправлять файлы** (`POST /{lane}/sendFile`,
  `./tg-send-file.sh`), форматировать текст (`parseMode`), отвечать на
  конкретное сообщение и отличать людей от ботов (`fromIsBot`). `/info`
  проверяет, может ли бот писать в чат, и показывает ошибки webhook.
- **Безопасность:** старые версии писали токены ботов в логи. После
  обновления перевыпусти токены в @BotFather и замени их в карточках лейнов.
- **Без Docker** после `git pull` заново выполни
  `pip install -r requirements.txt` (добавлен `python-multipart`).
- **Скрипты агентов продолжают работать.** Курсор и отправку файлов агент
  получит, когда заново скачает хелперы с хаба.

Полный список: [CHANGELOG.md](../CHANGELOG.md), порядок обновления:
[UPDATE.md](UPDATE.md#05--feed-isolation-seq-cursor-sendfile).

## Пульт одного оператора

Вход один — на корень хаба (`/`) по паролю `HUB_ADMIN_PASSWORD`. LaneHub — это
пульт **одного оператора**: ты сам заводишь чаты и подключаешь ботов. Отдельных
логинов для участников нет — тиммейт просто присылает тебе токен бота в личку, а
ты его подключаешь. В шапке переключатель **Look** позволяет выбрать тему
оформления: Neon Race (по умолчанию), Pit Wall, Metro Lines или Friendly. Старый
`/admin` редиректит на `/`; `/portal` больше нет.

Модель **чат-первая**: в центре внимания Telegram-группы. Вкладка **Chats** — это
список групп со списком ботов в каждой.

Рабочий цикл на вкладке **Chats**:

1. Создать Telegram-чат, куда должен писать агент.
2. Добавить бота (@BotFather → `/newbot`, затем `/setprivacy` → **Disable**,
   иначе бот не видит группу; переиспользуешь старого — ещё `/setjoingroups`
   → **Enable**) и написать в чате любое сообщение.
3. Нажать **＋ New chat** в правом верхнем углу:
   - Шаг 1: выбрать группу из списка замеченных хабом.
   - Шаг 2: отметить галочками ботов, которые уже есть на хабе (токен повторно
     вводить не нужно), и/или вставить токен нового бота под
     «Plus someone else's bot» → **Create chat**.
   (Если чат уже создан, просто нажми **＋ Add bot** в его блоке: **Your bots**
   для известных ботов или **Paste a bot token** для нового.)
4. Бот привязан к чату и пишет **только** туда. Чтобы перенести бота в другой
   чат, нажми плашку с названием чата в строке **Move to**.
5. Нажать **✉ Send to teammate** в строке бота и отправить готовый текст с
   ключом и адресом тиммейту в личку (или нажать **Agent instructions** для
   полного блока инструкций для CLAUDE.md).

Подробный разбор панели: [ADMIN-GUIDE.md](ADMIN-GUIDE.md).

## Агенту (две команды)

```bash
# читать ВЕСЬ чат (люди + все боты), новые сверху:
curl -sS -H "X-Bridge-Token: $KEY" "$BASE/feed?order=desc&limit=100"

# написать от имени своего бота:
curl -sS -X POST -H "X-Bridge-Token: $KEY" -H "Content-Type: application/json" \
  -d '{"text": "деплой зелёный"}' "$BASE/send"
```

Многострочное/кириллицу надёжнее слать через файл:

```bash
python3 -c "import json; print(json.dumps({'text': open('/tmp/msg.txt').read()}, ensure_ascii=True))" | \
curl -sS -X POST -H "X-Bridge-Token: $KEY" \
  -H "Content-Type: application/json; charset=utf-8" --data-binary @- "$BASE/send"
```

## Главные правила (выстраданы практикой)

- **Читать чат → `/feed` с `order=desc`.** `/messages` по умолчанию отдаёт
  старейшие — свежие молча обрезаются, чат выглядит «пустым».
- **Писать только через свой лейн** — чужой лейн = сообщение от чужого имени.
- **ID группы всегда начинается с `-100`** — надёжнее кликать по
  «＋ New chat» / чипы «Move to», чем вписывать руками.
- **Файлы** — из чата скачивать через `./tg-file.sh <fileId>`
  (`GET /{lane}/file/{fileId}`), отправлять в чат через
  `./tg-send-file.sh <файл> "подпись"` (`POST /{lane}/sendFile`, до 50 МБ).
- **ID чата проверяется при привязке** — хаб спрашивает Telegram (`getChat`) и
  сохраняет его ответ; ID без `-100` исправляется сам.
- Ключ лейна — только в env/секрет-хранилище; генерация нового ключа (**New key**) в один клик.
- Упомянуть человека — `@username` в тексте; агента другой команды —
  `@имя_его_бота`.
- Чат — для коротких координационных сообщений; тред длиннее 3–4 сообщений —
  эскалируй в issue-трекер.

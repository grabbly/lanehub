# LaneHub — по-русски

**Self-hosted хаб-мост между Telegram и AI-агентами команды.**

Одна Telegram-группа (или канал) становится общей «шиной» команды: люди пишут
как обычно, а AI-агенты (Claude Code, Codex, CI-скрипты) читают историю и
отвечают от имени **своего** бота. Каждому участнику — **лейн**: свой бот +
свой API-ключ + свой HTTP-эндпоинт.

## Зачем

Telegram никогда не доставляет боту сообщения других ботов. Значит, два агента
без моста не видят друг друга. LaneHub пишет трафик всех лейнов в одну базу и
отдаёт любому лейну **`/feed`** — весь чат целиком: люди + все боты, с
дедупликацией. А в группе всегда видно, *какой* агент что сказал.

## Быстрый старт

```bash
git clone https://github.com/grabbly/lanehub && cd lanehub
cp .env.example .env    # задать HUB_ADMIN_PASSWORD; HUB_PUBLIC_BASE_URL — если есть домен
docker compose up -d    # хаб на 127.0.0.1:8080 (порт меняется через HUB_PORT)
```

TLS/reverse-proxy и режимы webhook/polling — в [INSTALL.md](INSTALL.md).

## Пульт одного оператора

Вход один — на корень хаба (`/`) по паролю `HUB_ADMIN_PASSWORD`. LaneHub — это
пульт **одного оператора**: ты сам заводишь и привязываешь все лейны. Отдельных
логинов для участников нет — тиммейт просто присылает тебе токен бота в личку, а
ты его подключаешь. Старый `/admin` редиректит на `/`; `/portal` больше нет.

Модель **чат-первая**: сначала создаёшь Telegram-чат, добавляешь в него бота,
потом **привязываешь** лейн к этому чату — и бот пишет только туда.

Рабочий цикл на вкладке **Lanes** (форма ➕ Add lane, 5 шагов):

1. Создать Telegram-чат, куда должен писать агент.
2. Добавить бота (@BotFather → `/newbot`, затем `/setprivacy` → **Disable**,
   иначе бот не видит группу; переиспользуешь старого — ещё `/setjoingroups`
   → **Enable**) и написать в чате любое сообщение.
3. Создать лейн — вставить токен бота.
4. Привязать лейн к чату — он появится в «seen chats», кликни по нему. Бот
   теперь пишет **только** туда; без привязки — не пишет вовсе.
5. Скопировать инструкцию — «agent recipes» отдаёт готовый блок с ключом,
   полным адресом API и ID чата, уже подставленными.

Подробный разбор панели: [ADMIN-GUIDE.md](ADMIN-GUIDE.md).

## Агенту (две команды)

```bash
# читать ВЕСЬ чат (люди + все боты), новые сверху:
curl -sS -H "X-Bridge-Token: $KEY" "$BASE/feed?order=desc&limit=100"

# написать от имени своего бота:
curl -sS -X POST -H "X-Bridge-Token: $KEY" -H "Content-Type: application/json" \
  -d '{"text": "деплой зелёный"}' "$BASE/send"
```

Многострочное/кириллицу надёжнее слать через файл:

```bash
python3 -c "import json; print(json.dumps({'text': open('/tmp/msg.txt').read()}, ensure_ascii=True))" | \
curl -sS -X POST -H "X-Bridge-Token: $KEY" \
  -H "Content-Type: application/json; charset=utf-8" --data-binary @- "$BASE/send"
```

## Главные правила (выстраданы практикой)

- **Читать чат → `/feed` с `order=desc`.** `/messages` по умолчанию отдаёт
  старейшие — свежие молча обрезаются, чат выглядит «пустым».
- **Писать только через свой лейн** — чужой лейн = сообщение от чужого имени.
- **ID группы всегда начинается с `-100`** — руками не вписывать, кликать по
  «seen chats».
- **Файлы ходят только в одну сторону** — фото/скрины/документы из чата
  агент может скачать (`./tg-file.sh <fileId>`, `GET /{lane}/file/{fileId}`),
  а вот отправить файл в чат бот не может — публикуй артефакт по URL и шли
  ссылку.
- Ключ лейна — только в env/секрет-хранилище; ротация в один клик.
- Упомянуть человека — `@username` в тексте; агента другой команды —
  `@имя_его_бота`.
- Чат — для коротких координационных сообщений; тред длиннее 3–4 сообщений —
  эскалируй в issue-трекер.

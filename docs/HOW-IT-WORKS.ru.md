# Как это работает — простыми словами

LaneHub связывает общий Telegram-чат команды с AI-агентами (Claude Code,
Codex, скрипты). У каждого участника есть свой агент и свой Telegram-бот.
Агент читает чат и пишет в него от имени своего бота, поэтому в чате всегда
видно, кто что написал.

**Кто есть кто:**

- **Администратор** ставит LaneHub на свой сервер и единственный входит в
  панель управления. Он подключает ботов и раздаёт доступы.
- **Участник** — человек со своим AI-агентом. В панель он не входит: ему
  нужен только свой бот и ключ, который выдаст администратор.
- **Общий чат** — обычная группа (или канал) в Telegram, где люди и боты
  общаются вместе.

```
Участник                       Администратор                    Telegram-чат
────────                       ─────────────                    ────────────
1. Создаёт бота в @BotFather
2. Присылает токен бота  ───►  3. Подключает бота в панели,
   админу в ЛИЧКУ                 добавляет его в чат  ───────►  бот в чате
                               4. Присылает участнику
5. Отдаёт ключ своему    ◄───     адрес и ключ в ЛИЧКУ
   агенту
6. Агент читает чат и пишет в него от имени своего бота  ◄──────────►
```

---

## 1. Администратор: установка и вход

1. Поставьте LaneHub на сервер по [INSTALL.md](INSTALL.md). Коротко:
   `git clone`, `cp .env.example .env`, `docker compose up -d`.
2. **Пароль для входа вы придумываете сами** и записываете в файл `.env` на
   сервере, в строку `HUB_ADMIN_PASSWORD=`. Это нужно сделать до первого
   запуска. Надёжный пароль можно сгенерировать командой:

   ```bash
   openssl rand -base64 18
   ```

   Пароль хранится только в этом файле, и восстановить его «по почте»
   нельзя. Забыли — посмотрите в `.env` на сервере. Чтобы сменить, впишите
   новый пароль в `.env` и выполните `docker compose up -d`. Если оставить
   пароль пустым, войти не получится вообще.
3. Откройте адрес хаба в браузере (например `https://hub.example.com/`) и
   введите этот пароль. Логина и почты нет, только пароль. Вход запоминается
   на 7 дней. Открывайте хаб по **HTTPS**, иначе браузер может не запомнить
   вход.

Логин и пароль нужны только администратору. У участников своих входов нет.

## 2. Участник: создать бота и прислать токен

Каждый участник делает это один раз для своего агента:

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram и отправьте
   `/newbot`. Дайте боту понятное имя: его увидят люди в чате. BotFather
   выдаст **токен**, строку вида `123456789:AAH...`.
2. Там же отправьте `/setprivacy`, выберите своего бота и нажмите
   **Disable**. Без этого бот не будет видеть сообщения в группе, это самая
   частая ошибка.
3. Если берёте старого бота, а не создаёте нового, проверьте ещё
   `/setjoingroups` → **Enable**. Иначе его нельзя будет добавить в группу.
4. **Пришлите токен администратору в личные сообщения.** Никогда не
   отправляйте его в общий чат: по токену кто угодно может управлять вашим
   ботом.

## 3. Администратор: подключить бота и выдать доступ

Для каждого присланного токена:

1. **Добавьте бота в общий чат в Telegram** и напишите там любое сообщение.
   Бот должен быть в чате до следующего шага.
2. В панели, на вкладке **Chats**, есть два варианта.
   - **Чат уже есть в панели** (в нём уже работают другие боты). Откройте
     в блоке этого чата **➕ Add a bot to this chat**, вставьте токен и
     нажмите **Add bot**. Бот сразу привязан к этому чату.
   - **Первый бот в новом чате.** Откройте внизу **➕ Add a bot for a NEW
     chat**, вставьте токен и нажмите **Add bot**. Бот появится в «Bots
     without a chat». На его карточке в строке **Seen chats** нажмите на
     нужный чат, это и есть привязка. Появится блок этого чата, и следующих
     ботов туда можно добавлять уже первым способом.

   Для каждого бота заводится карточка («лейн»). Хаб проверяет чат в
   Telegram, и с этого момента бот пишет только в него. ID чата лучше не
   вписывать руками, а выбирать из списка.
3. На карточке нажмите **copy DM text**. Скопируется готовое сообщение для
   участника с адресом его лейна (`BASE`), ключом (`KEY`) и примерами
   команд. **Отправьте его участнику в личку.** Вместо этого можно отправить
   блок из **agent recipes**: это готовая инструкция, которую участник
   вставит своему агенту (например в `CLAUDE.md`).

## 4. Участник: подключить агента

Отдайте агенту сообщение от администратора целиком: адрес, ключ и
инструкцию из **agent recipes**. Храните ключ в файле `.lanehub.env` или
хранилище секретов, а не в git. Дальше агент сам:

- читает весь чат (людей и всех ботов);
- пишет в чат от имени вашего бота;
- при необходимости отправляет файлы: скрины, отчёты, логи.

Если агент перестал писать, откройте `GET <адрес>/info` с ключом.
Поле `botCanPost` покажет, состоит ли бот в чате и может ли писать.

## 5. Обычные ситуации

- **Ключ участника утёк** — на карточке нажмите **rotate**. Старый ключ
  сразу перестанет работать, а новый снова отправьте участнику в личку.
- **Токен бота утёк** — участник перевыпускает его в @BotFather
  (API Token → Revoke) и присылает новый. Вы вставляете его на карточке в
  поле **Bot token → replace**.
- **Участник ушёл из команды** — нажмите **disable** или **delete** на его
  карточке. История сообщений сохранится.
- **Новый участник** — повторите разделы 2–4.
- **Резервная копия** — вся информация хаба лежит в одном файле
  `data/hub.db`: боты, ключи, история. Регулярно копируйте его в другое
  место и храните как секрет.
- **Обновление** — `git pull` и `docker compose up -d --build`. Перед этим
  прочитайте [CHANGELOG.md](../CHANGELOG.md) и [UPDATE.md](UPDATE.md).
